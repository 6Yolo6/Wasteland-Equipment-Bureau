## 1. 执行纪律与阶段依赖

顺序为 **阶段 1 核查与决策 → 阶段 2 核心闭环 → 阶段 3 成长与体验 → 阶段 4 广告 → 阶段 5 原生验收 → 阶段 6 测试发布准备**。只按依赖安排，不承诺在若干小时内完成。

每阶段先建立可执行验收再实现；结束后运行实际存在的命令和手动用例，保存结果并报告。失败、缺配置、未拿到设备分别如实标记，不以“代码看起来正确”代替通过。允许工具缺失时继续设计／纯逻辑准备，但不得把后续阶段未完成工作包装成完整交付。

## 4. 体积、性能和资源预算

### 4.1 首包和完整包：项目预算，不冒充平台结论

平台核查的两份官方页面有“首包60M+”与“首包4M+、总包60M”的冲突，尚待后台／官方统一口径。项目先采用 **主包≤4MB、完整MVP≤15MB** 的保守目标；内部暂以十进制MB计（4,000,000／15,000,000字节）。压缩／解压、主包包含项、引擎是否计入与分包能力均待核查，不以预算达标替代后台通过。

| 主包预算项 | 拟定分配 |
|---|---:|
| 引擎实际计入部分、适配与业务脚本 | 2.40MB |
| 首局所需UI／图集 | 0.72MB |
| 必要短音效 | 0.16MB |
| 配置与基础数据 | 0.16MB |
| 清单及其他开销 | 0.16MB |
| 预留 | 0.40MB |
| 合计 | 4.00MB |

完整包15MB内部预算：主包4MB、其余美术6MB、其余音频1.5MB、字体0.5MB、其他1MB、预留2MB。所有数字都未实测；如实际引擎产物已突破分配，先评估已验证的裁剪／分包能力并调整设计，不伪报压缩结果、不假定平台支持分包。

每次构建登记主包、总压缩包、总解压目录、最大资源、引擎／脚本／图集／音频占比及配置版本；不把工作区目录大小当发布包大小。

### 4.2 内部性能目标

基准设备由阶段5按官方支持范围选定，至少覆盖一个相对低性能设备和一个长屏设备；型号／系统／运行时必须记录。以下是**待测目标**：正常战斗≥30fps，核心单tick耗时P95≤4ms，冷启动到可交互≤5秒，连续10局内存无持续单调增长；首轮采样后再给可复核的内存绝对上限。

可恢复存档初始预警预算256KiB，诊断日志轮转预算2MiB；这些是项目容量管理目标，不是平台存储配额。超过阈值先报警与分析，不能通过删除奖励账本或用户装备达标。帧率、启动时长、内存均标注采样方式与环境，不能从桌面预览外推真机。

### 4.3 原创资源与许可证清单

每件美术／音频／字体／第三方依赖登记：资源ID、作者、来源、许可文本／凭据、商用与改编权限、署名要求、修改记录、最终包内位置；原创资源登记制作记录，AI辅助资源保留来源与人工核查。无来源素材不进正式包。

首版需要角色1套、普通敌人3套、首领1套、装备14套、背包／按钮／组合标记、基础场景、胜败反馈和8类基础音效。优先复用**本项目原创**配色与形状语言，避免大量大图与长音频；不借用已有游戏美术、文案、音效或具体布局。
