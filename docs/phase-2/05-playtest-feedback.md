# 人工试玩反馈整改：先让玩家看懂，再验证差异化

日期：2026-10-15。规则版本：mvp-0.2.1；试玩使用 mvp-0.2.1-dev-all。

本轮依据用户实际试玩反馈，不再以“单元测试通过、能通关”代替“玩家知道发生了什么”。这是核心玩法的可理解性整改和一个差异化机制原型，不代表持久存档、完整成长、音频、广告或 TapTap 真机已完成。

## 1. 电池：确认了真实缺陷，不是玩家看错

旧代码每次都把缩短后的冷却向上取整到 0.1 秒。振齿短刃原间隔 0.7 秒，乘 90% 后的 0.63 秒被反复取整回 0.7 秒，10% 加速完全消失。电池直接供电也没有列入旧“组合数量”，进一步造成没有生效的印象。

现改为整数定点的累计攻击时刻，第 n 次攻击在 ceil(n × 基础冷却 × (1−加速) / tick) 执行；不把每次取整损失重新累加。首次攻击仍等到下一模拟步，后续保留余量。短刃接电后前10次攻击发生于0.7、1.3、1.9、2.6、3.2、3.8、4.5、5.1、5.7、6.3秒；不接电6.3秒只能攻击9次。

- 明确区分基础间隔和装配后的**平均间隔**，不把0.63秒伪装成每次严格相同的帧间隔。
- 电池选中时显示供电是否接通、接到了哪把武器、实际间隔变化与共边标记。
- 拖动时只在临时合法布局上计算收益；松手才提交，失败仍保持原布局。
- 正交共边才算，斜角和隔空不算；多格武器接触任一占用格即可。同类电池不叠加。

代码：[冷却与装配](<D:/taptap/Wasteland Equipment Bureau/game/assets/scripts/core/loadout.ts>)、[攻击调度](<D:/taptap/Wasteland Equipment Bureau/game/assets/scripts/core/combat.ts>)。

## 2. 教学：从知道操作，到知道为什么这样摆

新增六页出勤手册：首次开始自动出现，可跳过；右上角“规则 / 教程”随时重看。

1. 出勤目标与整理→战斗→补给流程。
2. 共边/斜角对照图，电池直接供电与护板加伤。
3. 急救、定时治疗、穿甲消耗的触发与次数。
4. 敌人出手、武器选敌、伤害顺序、撤离时限。
5. 铜线错峰检修的合法布局和触发过程。
6. 洁净急救、惯性齿组的中心装备与三件套图示。

装备详情不仅写已触发效果，也写尚未拼成的组合配方。缺少电池、武器数量不够、处于备存、全局组合已达上限等原因可查看。较长内容分页，不靠缩小至不可读或静默截断来塞进一屏。关键小数不会在换行时拆成两段。

手册、装备详情和战报不会修改布局、消耗次数或推进战斗；每个弹窗只解除自己的暂停原因，不覆盖后台暂停。是否看过教程目前只保留在当前预览会话，刷新会再次出现；持久保存尚未实现。

## 3. 战斗：每个数字有含义，每次变化可复盘

### 撤离时限

旧“区域压力”实际上只是45秒的波次超时限制，并没有持续增伤机制。现改名为**撤离倒计时**，显示剩余秒数，明确“未清场即失败，不会随时间暗中加伤”。

### 敌人攻击

- 敌人卡显示当前生命、护甲、每击伤害、攻击间隔、距离下一击的时间和攻击目标。
- 当前普通敌人都按各自固定计时攻击装备员，区别主要是伤害、频率和护甲；没有假称已实现复杂 AI。
- 玩家武器从左起选择存活目标。霰器溅射下一目标，喷嘴最多命中3名敌人。
- 敌人伤害先扣减伤，再由护盾吸收，剩余才扣生命；普通伤害最低1。首领低于半血才会加快攻击，不是“压力条”导致。

### 武器与消耗品

- 设备卡显示装配伤害、平均间隔、下一击倒计时与已开火次数。
- 急救匣：受生命伤害后仍存活且生命≤40%，自动回复；仅护盾受击、满血或致死不会触发。
- 盐水：每8秒一次，最多4次；满血也消耗机会，日志明确显示实际回复0。
- 除锈药：自动供给下一次基础攻击，最多3份；多目标共享一份，无甲也消耗。
- 消耗次数每波重新补充，装备本身不消失。超过一页的设备可以翻页，未只显示前六件后隐藏其余设备。
- 命中数字、攻击线、护盾/生命分账、检修提示提供即时反馈；最近战报保留本波最近160条有效事件，不会随着下一空帧消失，可暂停展开。

读模型与战报：[RuleReadout.ts](<D:/taptap/Wasteland Equipment Bureau/game/assets/scripts/presentation/RuleReadout.ts>)。

## 4. 差异化原型：错峰检修

不以“工业题材皮肤＋常见加伤”宣称原创性已经达标。本轮把原来的纯冷却组合 C02 改为可观测的时序干预：

| 项目 | 当前规则 |
|---|---|
| 配方中心 | 铜线接驳器 |
| 接线要求 | 铜线同时正交接触1块电池与2件不同实例的武器；一件武器接触两格不算两件 |
| 被动收益 | 获选的两把武器平均冷却 -10%；与电池直接供电合计上限20% |
| 脉冲条件 | 两把接线武器分别完成一次基础攻击；同一把连打不代替另一把 |
| 脉冲作用 | 最早将出手的存活敌人，其下一次攻击延后0.3秒；时间相同按出生顺序选取 |
| 资源边界 | 每波最多3次，只有1条有效回路，不能无限控制 |
| 因果顺序 | 本 tick 武器先行动，脉冲可延后原本同 tick 将发生的敌人攻击；不能撤回已经造成的伤害 |
| 不变的约束 | 追加伤害不另充一次脉冲，不额外抽随机数，不额外耗药；最后敌人已死不浪费脉冲 |

**差异化方向是“有限格子内的检修布线与攻击时序”，不是复制某款游戏的物品表、组合名单或关卡。** 本次保留项目自己的代码绘图和名称，没有导入其他游戏素材、代码或品牌。通用的网格背包、邻接与自动战斗属于本项目使用的基础玩法形式，不能据此宣称全球独创或完成相似性/知识产权审查。

这个原型仍需人工检验：玩家能否预判何时产生脉冲、能否理解它延后了哪次攻击、慢重武器与快武器的接线是否产生值得取舍的策略。当前普通敌人的差异仍偏数值，后续应先验证这一核心方向，再设计更鲜明的检修对象与对应装备规则；不靠继续堆同质装备、成长或广告掩盖问题。

## 5. 版本与复现边界

规则版本升至0.2.1，旧版本运行快照不能混用。为了能在同一工单上比较加速修复前后差异，本轮显式保留原随机命名空间：普通 mvp-0.2.0，开发 mvp-0.2.0-dev-all。内容版本与随机流命名空间在内容配置中分别标识；没有为让测试过关而临时赠送装备或改生命/伤害。

默认种子仍为20261015，标准池仍有10件初始解锁，当前开发界面开放14件。金币仍是会话内临时值；没有持久存档、广告、真实登录或原生包。

## 7. 下一次人工试玩重点

1. 选振齿短刃，把电池先放斜角，再放共边；看供电状态与0.70→0.63秒的变化。
2. 只看新手册，判断护板、医疗三件套和机械三件套分别要贴谁。
3. 战斗中预测最近要攻击的敌人，核对攻击后的减伤/护盾/生命分账。
4. 打开战报确认一次实际用药，关闭后应继续原来的时刻，而不是跳过伤害。
5. 有铜线和第二把武器时，搭一条错峰检修回路；判断其脉冲是否真正构成可理解、值得布局的决策。
