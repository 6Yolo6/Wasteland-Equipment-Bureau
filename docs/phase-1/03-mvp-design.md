# 《废土装备局》MVP 设计提案

- 编写日期：2026-10-14（Asia/Shanghai）。
- 状态：**阶段 1 提案；未实现；所有玩法数值、性能与留存目标均未实测，不能视为测试通过。**
- 目标产品：TapTap **原生小游戏**，不是 H5 小游戏、普通 APK 或其他平台小程序。
- 平台事实以 [平台核查文档](<D:/taptap/Wasteland Equipment Bureau/docs/phase-1/02-platform-verification.md>) 为准；本文不确定 SDK 版本、包体格式或官方包体上限。
- 配套：[架构](<D:/taptap/Wasteland Equipment Bureau/docs/phase-1/04-architecture.md>)、[路线与测试](<D:/taptap/Wasteland Equipment Bureau/docs/phase-1/05-roadmap-and-tests.md>)、[广告详细设计](<D:/taptap/Wasteland Equipment Bureau/docs/phase-1/06-ad-design.md>)。

## 1. 范围与完整闭环

原创主题：玩家是废土补给站的装备管理员，利用拾来的机械零件布置随身装备，击退回收场的失控机具。第一版只有 1 名角色“值班装备员”、14 件装备、3 种普通敌人、1 个首领和 5 波战斗。

流程：主菜单 → 普通局选择初始武器／每日挑战固定配置 → 备战整理 → 自动战斗 → 战利品选择 → 下一波备战 → 第 5 波首领 → 胜败结算 → 图鉴、解锁和成长。

- 每局 **3–6 分钟是设计目标，不是实测结果**。初始选择约 20–35 秒、5 次整理合计约 60–100 秒、5 次战斗合计约 75–125 秒、4 次选战利品约 20–40 秒、结算约 10–20 秒；此拆分仅供初次调参。整理不强制倒计时；教学、广告、后台时间单独统计。
- 普通流程必须不看广告也能从开始到结算。失败直接结算、保留原战利品、领取基础金币都是有效路径。
- 只做本地游戏与必要的平台适配；不做 PVP、付费商城、账号服务器、云数据库、跨设备存档或排行榜。
- 未实现功能不放可点击的占位按钮。开发预览必须标明环境，模拟广告不能显示成真实广告收入。

## 2. 背包与交互规则

### 2.1 坐标、形状和旋转

固定 **5 列 × 6 行**；坐标原点在左上，x 为 0–4，y 为 0–5。装备定义包含非空、无重复、四连通的整数格偏移集合。实例保存稳定 instanceId、生成序号 spawnIndex、定义 ID、锚点和 rotation（0／90／180／270 度）。一个实例同一时刻只能在背包或备存区中的一个位置。

- 锚点是旋转并归一化后包围盒的左上角，不要求该格本身被形状占据。
- 顺时针旋转：每格 (x,y) 变为 (-y,x)，随后分别减去最小 x、最小 y，得到非负偏移；按 y、x 排序。四次旋转必须还原原形。对称形状允许视觉结果不变，不能额外复制格子。
- 放置合法当且仅当所有实际占用格在边界内、无重叠，且装备定义有效。包围盒中的空洞不算占用。
- 旋转按钮只改变拖动预览；确认放下才提交。取消拖动回到原位置与原朝向。

### 2.2 放置、单物交换与回滚

每次操作都是带 expectedRevision 的单个事务；拖动预览不修改正式背包。校验时先排除被拖动实例，再收集目标格覆盖的**不同实例**：

| 情形 | 事务结果 |
|---|---|
| 目标合法且没有其他实例 | 移动／从备存区装备，提交一次 revision 变更 |
| 恰好覆盖 1 个实例 B，拖动实例 A 原在背包 | 同时移除 A、B；A 以目标锚点与目标朝向放置，B 以自己的原朝向放到 A 的原锚点；校验两者、其他物品和边界后一次提交 |
| 恰好覆盖 1 个实例 B，A 原在备存区 | A 进入目标；B 进入 A 原来的备存区列表位置；整笔校验后一次提交 |
| 目标覆盖 2 个及以上实例 | 拒绝；不连锁推挤、不自动寻找其他位置 |
| B 在交换后越界／与 A 或其他物品冲突、目标越界、revision 过期 | 整笔拒绝，背包、朝向、备存区顺序、组合与实例总数全部不变 |
| 背包物品拖到备存区 | 卸下并保留实例，不分解、不出售、不删除 |

备存区是本局可滚动列表，MVP 不设置硬容量、不自动丢弃。新获得的装备全部先放入备存区，不强制覆盖背包。满包时可继续整理、把旧物品放入备存区，或者明确放弃尚未领取的战利品；已领取物品不得因空间不足消失。

一次操作中“占用多格但仅碰到同一件装备”仍是单物交换。所有交换、旋转和撤销后，都重新从最终布局推导组合，不对旧属性做增减补丁。

### 2.3 撤销边界与反馈

- 每次进入备战时保存检查点；支持逐步撤销到**本次备战开始**。撤销包含背包位置、朝向、备存区顺序，不跨越战斗、战利品领取、广告奖励或结算。撤销本身也是新事务，revision 单调递增，不恢复历史 revision，避免旧拖动请求重新变成有效。
- 点击“开始战斗”成功封存布局后清空该阶段撤销历史；战斗、失败待选、战利品和结算阶段拒绝移动、交换、旋转、撤销命令。
- 可放置：绿色轮廓＋格子标记；不可放置：红色轮廓＋具体原因；交换：高亮两个实例；组合：连线、图标与文字说明。信息不能仅靠颜色区分。
- 放下失败回到源位置，显示“越界”“需先腾出空间”或“装备状态已变化”；不得用失败音效替代原因提示。

| ID | 名称／类别 | 格偏移 | 基础效果提案 |
|---|---|---|---|

“消耗品”使用每波补充的次数／计数器；耗尽只变灰，不销毁装备实例，复活不补充次数。I11 的多目标攻击只消耗一次强化，各命中共用此次强化；按物品 spawnIndex 选择尚有次数的来源。

普通局初始包：I01／I02／I03 三选一，加 I05、I07、I09。每日挑战固定选择 I01，不读取普通局的武器选择。初始装备先进入备存区，教程引导玩家亲手放置。

普通敌人胜利后共进行 4 次战利品选择：每次提供 3 份补给方案，每份包含 2 件装备。当前提案允许同定义的不同实例；从模式对应装备池按权重抽取，展示后保存结果，退出重进不重抽。领取一份后其他方案失效；可以明确“放弃本次补给”继续。首领之后直接结算。

随机事件首版只做一个可配置事件：“回收偏好”。在第 2 波胜利后，以配置概率给**下一次**补给池的武器权重乘 2，其余不变；无额外弹窗、无新增广告入口。事件是否发生、修正有效期和结果都写入本局状态；禁用事件时正常流程仍完整。

## 4. 四邻接、组合去重与属性上限

四邻接定义：两个不同实例至少有一对实际占用格的曼哈顿距离为 1。斜对角、隔空、包围盒接触、自身格之间均不算；共享多条边只生成一条实例邻接关系。

| 组合 ID／名称 | 条件 | 效果与数量上限 |
|---|---|---|
| C01 屏护射位 | 武器四邻接至少 1 件 I05 | 该武器基础伤害 +2；每武器一次，全布局最多 3 把武器获益 |
| C02 并联回路 | I12 同时四邻接 I07 与至少 2 把不同实例的武器 | 选 spawnIndex 最小的 2 把邻接武器，冷却各缩短 10%；全布局最多 1 个 I12 生效 |
| C03 洁净急救 | I09 同时四邻接 I10 与 I11 | 该急救匣单次回复 +6；全布局最多 1 个 I09 生效 |
| C04 惯性齿组 | I03 同时四邻接 I08 与 I13 | 该短刃每第 3 次基础攻击额外造成 5 点伤害；全布局最多 1 把短刃生效 |

- 组合候选按 ruleId、锚点 spawnIndex 排序；参与者有多种选法时取满足条件的字典序最小实例集合。效果唯一键为 ruleId + anchorInstanceId；共享多格边、多个等价参与者不会重复发同一效果。
- 先匹配、去重、套用组合数量上限，再按 recipient + effectKind 聚合并限幅；规则不能因配置对象遍历顺序变化而改变结果。
- 初稿上限：攻速缩短总计 20%；暴击率 35%；平伤减免 3；单武器布局额外基础伤害 +6；护盾 80；最大生命 200。所有数值为可版本化参数。
- C04 额外伤害标记为组合伤害，不增加“基础攻击次数”，不再次触发自己，也不额外消费 I11；击杀事件对每名敌人只发一次。
- 整理界面展示实际获得的组合、上限被截断的效果及最终属性，不能只显示“已组合”却不说明收益。

## 5. 战斗、敌人与五波配置

### 5.1 确定性战斗约定

- 基础生命 120；普通局可叠加局外生命升级，每波之间不自动满血。首波按封存后的最大生命满血开战；之后更换增血装备只提高上限，减低上限时当前生命向下截断，装卸不能刷回复。
- 逻辑固定步长 **100ms**，渲染可插值。战斗不读取帧率、系统时间或广告时长；每波首个攻击在其冷却 tick 到期时发生。
- 每 tick 固定顺序：起始／定时状态 → 玩家基础攻击及其即时衍生效果（武器 spawnIndex）→ 仍存活敌人的攻击（敌人 spawnIndex）→ 终局检查。击杀后的敌人本 tick 不再攻击；每次伤害后立即处理护盾、生命、仍存活条件下的急救。死亡不能靠同 tick 随后的普通回复抹去。
- 默认目标为存活敌人中 spawnIndex 最小者；多目标也按此顺序选取。每次基础攻击只做一次暴击抽样，所有命中共用该次结果。
- 数值采用整数／万分比：冷却为 max(3, ceil(基础冷却 × (10000−攻速缩短) / 10000))；先累加基础伤害加成，再计算倍率并向下取整，再扣除有效护甲，普通伤害至少 1。加血、护盾和计数均有边界。
- 每波默认硬时限 450t（45 秒）；到时仍未分胜负视为“压力失控”失败。终局优先级：玩家生命 ≤0 为败；否则敌人全灭为胜；否则检查超时。每波最多产生一个终局事件。

### 5.2 敌人与波次初稿

具体生命／伤害／冷却的平衡数值在阶段 2 配置与实测，当前仅锁定行为契约。每个敌人由数据中的行为类型、参数、显示资源 ID 和稳定出生序号创建，不通过 UI 判断行为。

| ID／敌人 | 唯一行为契约 |
|---|---|
| E01 钩索拾荒机／普通 | 低生命、较短攻击间隔，单体攻击；无随机闪避 |
| E02 冲铆搬运机／普通 | 较高单次伤害、较长攻击间隔；攻击前有表现层预警 |
| E03 厚壳巡检机／普通 | 较高生命和固定护甲，稳定攻击；用于验证穿甲与持续输出 |
| B01 炉芯回收车／首领 | 首次降到最大生命 50% 以下时仅转阶段一次，后续攻击间隔按配置缩短；不召唤第五种敌人 |

波次：1＝E01×2；2＝E01＋E02；3＝E01×2＋E03；4＝E02＋E03×2；5＝B01。数据校验必须保证引用存在、数值有限、冷却为正整数、波数等于 5；不把“能加载配置”当成“已可通关”。

### 5.3 失败、复活与终局边界

失败先进入“失败待选”并冻结战斗，不立即结算金币。玩家可直接结束本局；符合广告策略时可自愿申请复活。每日挑战禁用广告复活。

复活提案：**每局最多一次**，在当前失败快照继续，不重开该波、不重抽敌人、不倒带随机数。生命变为 ceil(最大生命×50%)，护盾清零，获得 10t 免伤；敌人生命、冷却、已消耗次数、击杀、组合计数、战斗 tick 与 RNG 状态全部保留。波时限变为 max(原时限, 失败 tick＋100)，因此超时失败复活后也有 10 秒机会，而非无限重置时限。

奖励事务成功提交才恢复逻辑；重复奖励回调不能重复加血、延长免伤或时限。拒绝、广告失败、未完整观看都保持失败待选，可直接结算。主动放弃后到来的广告回调不能重新打开已结算的战斗，归属处理见广告设计。

战斗统计：每件武器基础／组合实际伤害、原始伤害与过量伤害、受到伤害、护盾吸收、实际治疗、击杀数、组合触发次数、每波 tick、复活次数、胜败原因。实际伤害不超过目标当时可损失的生命；展示统计不参与发金币。

## 6. 随机数、每日挑战与局外成长

### 6.1 随机流与数据版本

所有随机行为使用显式种子和可保存状态。根种子按用途派生独立流：敌人／波次、战斗每波、战利品每次机会、随机事件、纯表现。广告重试、UI 特效抽样不能改变战斗或其他波的掉落。

同一 contentVersion、种子、模式、初始状态与操作序列应得到相同事件序列。不同版本不承诺同种子同结果。随机流算法与版本、种子派生方法和参考向量在阶段 2 固定；范围采样须无取模偏差，拒绝 NaN、负权重和总权重为零的配置。

与配套广告设计一致，**战利品广告重抽整局最多成功一次，不按波刷新**。随机结果使用原战利品机会下独立的 reroll 流，稳定奖励键只标识该局重抽资格，原 waveId／opportunityId 另存用于归属。成功发奖才替换并持久化新方案与整局次数；失败不改旧方案、不消耗资格。其他广告频控以配套广告设计为准。

### 6.2 每日 UTC+8 挑战

- 日期采用 **UTC+8**，不随设备显示时区变化；由 Clock 适配层提供可信程度有限的本地时钟，再生成日期键 YYYY-MM-DD。
- 种子输入固定为项目命名空间、dateKey、contentVersion；不含用户 ID、金币、图鉴、局外升级或随机登录信息。
- 使用固定 14 件装备池、固定权重、固定角色基础属性与初始包；忽略普通局解锁限制和局外强度。相同日期／内容版本／操作序列可重复复现。
- 每日挑战不启用广告复活、广告重抽或广告金币翻倍，避免比较被广告机会影响。允许任意重试，只记录本地最佳表现，不做在线公平性承诺。
- 开局锁定日期和版本，跨午夜不改变进行中的挑战；返回菜单新开挑战才读新日期。
- 每日首次胜利奖励暂定 20 金币，失败及同日重复胜利不重复给挑战奖励；去重键按 dateKey，不因同日内容更新再领。此金额仍待平衡。
- 没有服务器时不能防改系统时间、存档篡改或跨卸载重复领奖；UI 和发布说明应如实说明。

### 6.3 金币、图鉴、解锁、成就

普通局基础金币暂定：4×已胜波数＋通关额外 12；主动放弃按已胜波数结算，不算通关。钱包加法和本局终局标记同次提交，一局只能结算一次。双倍奖励仅**补发本局基础金币**，不是把整个钱包乘二。

- 初始解锁 I01、I02、I03、I05、I06、I07、I08、I09、I11、I13；其余 I04、I10、I12、I14 依次拟用 25／35／45／60 金币解锁。每日挑战使用完整池不受影响。
- 生命升级 3 级，每级 +5 最大生命，拟定费用 50／90／140；只影响普通局，购买和扣款原子提交，余额不足不扣款。
- 图鉴区分“见过”“获得过”“已解锁”；见过不自动解锁；单局装备实例不变成永久库存。
- 首版成就：首次通关、首次激活 C02、一次无复活通关；各用稳定成就 ID，一次性金币奖励单独记账，重复展示不能重复领奖。
- 结算明确告知“本局装备回收，保留金币、图鉴、解锁、成就与记录”，不能在玩家仍整理时清空物品。
- 本地保存版本化全状态，包括未结束单局、随机状态、成长和奖励账本；损坏恢复、迁移及未来版本保护见架构文档。不承诺跨卸载恢复或云同步。

## 7. 广告边界、教程与用户体验

广告业务只依赖项目自己的 AdService，战斗与背包不得依赖 SDK。三个入口为失败待选复活、战利品重抽、普通局结算补发基础金币；额度、同意提示、失败处理和完播证据由配套广告设计统一定义，不在本文件复制官方 API 表。

**本项目的保守体验策略**：首局从开局至结算整局不展示广告，结算翻倍也禁用；只有首个非主动放弃的普通局正常胜败结算并成功存档，才解除全局首局保护，且该局结算本身仍禁广告。之后还须满足有效前台体验至少60秒及平台核查确认的其他首次体验／频率条件。每日挑战全程不展示广告。这是产品提案，不冒充平台原文；正式策略取平台要求与产品限制中更严格者。

教程只在初次普通局分步展示：放入武器 → 旋转一次 → 放入护板看到组合 → 开战 → 选择补给 → 撤销操作。可跳过或重新查看；跳过不跳过首次广告保护。教程不强制用户观看广告，也不把“必须激活某组合”作为开战条件。

- 竖屏基准画布拟为 720×1280；布局适配安全区、窄屏、长屏与平板留白，不直接按设备像素定位。
- 主操作位于下半屏；拖动时物品预览偏移到手指上方；触控目标拟不小于 44 个逻辑单位。旋转、撤销、开战有清楚标签，不与广告按钮混淆。
- 支持关闭音效／音乐、减少闪烁；组合与受击反馈兼有文字／形状，不依赖色觉或声音。
- 基础音效：拿起、落下、无效放置、组合生效、射击、受击、胜利、失败。使用原创合成／录制或许可明确资源；轻震仅在目标平台能力验证后可选启用。
- 前后台、广告展示和系统中断冻结战斗；返回后先恢复界面并由明确的继续流程解冻，不把后台经过时间补算成伤害。

## 8. 内容、性能与验证目标

所有装备图形、角色、敌人、UI、文案、音频均新制作，不借用现有游戏的素材或具体关卡。每项外部资源登记来源、作者、授权、商用／改编许可、署名要求和凭据；字体与依赖也列入许可证清单。阶段 1 未产出这些资源。
